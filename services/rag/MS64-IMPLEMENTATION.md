The upload dialog contains File, Who can use this document?, and Upload. New files default to Admin only; explicit replacements prefill the current audience. The server derives a bounded sanitized title from the filename. Matching filenames never identify an existing document. Transfer success alone never means accepted processing; durable finalize acknowledgment closes the dialog and shows Processing. Repeated submissions after an ambiguous response first read request-scoped state. The existing write fence prevents double clicks. Preview is optional and read-only, with no technical review or Publish controls. Legacy READY files require a fresh explicit file upload.

New upload admissions call `upload_auto`, recording actor, scope, document/version, request, generation, revision and audience in a durable version-bound intent. Finalize adds immutable source hash/size. Existing finalize idempotency, private non-upsert storage, job uniqueness, five-attempt retry policy, leases and tombstones remain authoritative. Ordinary logout does not revoke accepted intent; deactivation blocks publication. A retry preserves the selected audience and source while binding a new generation; a changed document revision requires fresh upload intent.

The worker validates normalized offsets, the complete extraction hash, supported parser contract, structural references and preservation of source material before sending `kb-auto-v1`. SQL independently validates the existing chunk/content/structure manifests, scope, current administrator authority, intent bindings, generation, lease, revision and embedding catalog. Unsupported embedded content, tracked changes, unresolved references and mixed-content uncertainty stop processing. Ordinary Markdown, native Word content/tables, text PDF and eligible OCR results retain the existing extraction pipeline. System verification is integrity checking, not certification of business policy or perfect OCR accuracy.

Automatic preparation uses conservative complete-document dependencies. Every operative passage remains required; no inferred local scope or MS-59 passage-purpose overlay is generated. A document whose conservative closure exceeds the existing six-source retrieval budget fails with a file-level remedy. This is an existing retrieval compatibility guard, not a new file-size/page-count product limit. More selective automated scope analysis remains unsupported and must never discard qualifications to fit. Existing answer-time byte, quotation and model budgets still apply and may yield an honest context-limit outcome for a particular question.

Worker completion and publication run in one PostgreSQL transaction. A successful transaction updates the active version, predecessor state, selected audience, catalog epoch, system audit, completed lease receipt and one Available notification. A crash before commit leaves leased work recoverable; a lost response reconciles the committed exact lease. Pending/failed replacements preserve the predecessor and its permissions. Immediate audience changes and removal invalidate stale completion. No browser callback publishes content.

Human review fields remain untouched: `review_acknowledged=false`, `structure_reviewed=false`, null reviewer/time and no document-review identity/evidence-role overlay. `system_verification` records the versioned policy and exact source/content/structure/generation/parser/embedding/audience binding. Compatible availability, legacy expansion and MS-59 graph readers accept this separate provenance. Existing human publications are not rewritten. Existing jobs without intent remain on their historical READY path and never automatically publish.
